# 服务区域调整前后覆盖分析

用于比较区域边界变化、居民位置精度和服务承办关系对覆盖指标的影响。所有位置为合成片区编码。

`fixtures/` 保存 UTF-8 合成业务资料，字段、关系和时间含义见 `DATA.md`。项目使用 Python 3.11 标准库；资料结构检查可用 `python3 -m unittest discover -s tests -v` 运行。

## 应用：`service_coverage`

区域服务覆盖分析应用：在多期边界版本、责任移交与位置精度分级并存的情况下，
对居民诉求做归属解释与可比汇总，回答“人数变化是实际需求变化还是辖区划分变了”。

```bash
# 生成 Markdown 报告（打印到标准输出）
python3 -m service_coverage --fixtures fixtures

# 指定统一空间口径的边界版本，并输出文件
python3 -m service_coverage --fixtures fixtures --unified-version new \
    --md report.md --json report.json
```

### 两种口径

- **当时责任口径（as-was）**：按诉求发生当日的有效边界与移交状态解释责任。
  已接受（accepted=yes）的移交自生效日起转移责任；待确认（pending）的移交
  不视为已转移，责任留在原网格。旧月份永远按当时责任解释，
  新边界不会被套用到旧记录上。
- **统一空间口径（unified:<版本>）**：所有期间统一使用指定的同一边界版本归属，
  用于跨期间可比汇总。它是分析参照，不代表也不改写当时的责任事实。

### 汇总纪律

- 位置精度 exact 为确定归属；range 只按范围估计（候选网格等份额分摊），
  估计与确定分列，绝不把范围地址当作精确网格。
- 承办量按实际承办网格统计，归属需求按口径归属统计；跨界承办不代表需求
  属于承办方辖区。每条诉求在归属侧份额合计恰为 1、在承办侧恰计 1 次，
  跨界对象不重复计算。
- 来源空值表示“未给出该事实”，不等于 0、否或业务终态；人口缺失不解释为
  无人居住，人口不完整的网格不给出人均数值。
- 来源记录只读：边界更新以新版本表达，旧责任记录不被无痕改写。

### 报告内容

数据来源与版本、口径说明、逐诉求归属明细、网格×期间指标（人均诉求、
服务覆盖率、自办率、跨区承办、需求外流）、归属×承办矩阵、片区级需求序列
（口径无关的稳定视角）、口径对比（划分调整 vs 需求变化）、数据质量与缺失
清单、完整性校验。
